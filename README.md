## Graftcode version

This fork converts **demo1** (Flask `webapp` → gRPC `users` service) to [Graftcode](https://www.graftcode.com).
The topology is unchanged: the Users service is still its own process on port `50051`, and the Flask
webapp (port `5000`) and `sample_client.py` are separate processes that call it remotely. Only the
transport changed: the gRPC server/stub pair is replaced by **Graftcode Gateway (`gg`)** hosting a
plain Python module, and the consumers call it through a **graft package generated by Graftcode**
(`graft-pypi-users-service`), not a hand-written client.

### What changed

| File | Change |
| --- | --- |
| `demo1/grpc-services/users/graft/users_graft.py` | New. Public `Users.create_user` / `Users.get_users` static methods returning a `User` DTO. They call the **existing** `UsersService` servicer in `server/server.py`, so the domain logic is untouched. |
| `demo1/grpc-services/users/graft/pyproject.toml` | New. Module name `users-service` → generated graft `graft-pypi-users-service`. |
| `demo1/grpc-services/users/run-graft-server.sh` | New. Starts `gg --runtime python --modules ./graft/ --port 50051`. |
| `demo1/webapp/app.py` | `ServiceClient(users_service, 'UsersStub', 'users', 50051)` + `GetUsers(request)` + `MessageToJson` → graft `Users.get_users(...)` with `GraftConfig.host = ws://users:50051/ws` (override with `USERS_HOST`). Same route, same JSON output. |
| `demo1/grpc-services/users/sample_client.py` | Same swap for the CLI client; the `ip` gRPC metadata is now sent as a Graftcode header (`GraftConfig.set_headers`) and the servicer still receives it via `context.invocation_metadata()`. |
| `.gitignore` | Ignores the `gg` runtime cache `.graftcode/`. |

Nothing was deleted. `server/server.py`, the `.proto` files, `client_wrapper.py`, `demo2/`, and
`grpc-middleware/` are unchanged. The original gRPC server (`run-server.sh`) still runs, and
`sample_client_demo*.py` still use it. The Dockerfiles and docker-compose files were **not** updated;
use the local steps below.

### Diff vs upstream (`git diff --numstat amitsaha/python-grpc-demo@813e549`, code only, README excluded)

- 6 files changed, **106 insertions, 28 deletions**
- Consumer client code (`webapp/app.py`, `sample_client.py`): **28 lines removed, 24 added**. No gRPC
  channel, stub, request messages, or protobuf-to-JSON code is left in the consumers.
- Producer glue (new): `users_graft.py` 64 lines, `pyproject.toml` 6, `run-graft-server.sh` 9.
  The facade is extra code in this fork because it wraps the gRPC servicer without changing it. A
  Graftcode-native service would just be the plain class.

### Run it locally (tested with gg 1.4.2, Python 3.12 host / 3.13 client)

```bash
# 0. Generate the protobuf modules (unchanged upstream script; the servicer still uses them)
pip install grpcio grpcio-tools protobuf graftcode-context flask
cd demo1/protos && ./build.sh && cd ../..

# 1. Users service: host the module with Graftcode Gateway (own process, port 50051)
#    gg: https://github.com/grft-dev/graftcode-gateway/releases
#    If gg reports "Cannot find Python", point it at libpython:
#    export HYPERTUBE_PYTHON_RUNTIME_PATH=/path/to/libpython3.12.so
#    (and add your venv's site-packages to PYTHONPATH so the host can import grpcio/protobuf)
GEN_PY=$PWD/demo1/protos/gen-py demo1/grpc-services/users/run-graft-server.sh

# 2. Install the generated graft. Copy the exact command from the gg log or from:
curl -s http://localhost:50051/pypi
#    e.g. pip install --extra-index-url https://grft.dev/simple/<GUID>__free graft-pypi-users-service==1.0.0

# 3. Webapp (second process) calls the Users service through the graft
cd demo1/webapp && USERS_HOST=ws://localhost:50051/ws flask run
curl localhost:5000/users/
```

Measured output (gg pid 159198 on :50051, Flask pid 159764 on :5000; separate `sample_client.py` pid 159800):

```
$ curl localhost:5000/users/
{
  "user": {
    "username": "alexa",
    "userId": 1
  }
}{
  "user": {
    "username": "christie",
    "userId": 1
  }
}
$ USERS_HOST=ws://localhost:50051/ws python sample_client.py
User created: tom
user { username: alexa user_id: 1 }
user { username: christie user_id: 1 }
```

The JSON matches what the original gRPC version returns. The Users process also printed the
forwarded header in its `CreateUser` metadata: `'ip': '127.0.0.1'`.

**Known limitation (gg 1.4.2, Python host):** a *parameter* of type `list[User]` (array of DTOs)
fails on the host with `module 'graft.users_graft' has no attribute 'User[]'`. So `get_users` takes
two parallel primitive lists (`usernames: list[str], user_ids: list[int]`). Returning `list[User]`
works.
